# Telegram Expense Bot

Telegram-бот для учёта расходов: Python, aiogram 3, FastAPI и PostgreSQL.

## Возможности
- Добавление расхода сообщением, например «Кофе 300» или «Такси 1 000».
- Выбор категории через inline-кнопки.
- 10 начальных категорий и пользовательские категории.
- Статистика за текущий месяц и последние 10 расходов.
- Отдельные данные для каждого Telegram-пользователя.
- Webhook-режим для serverless-хостинга; состояние незавершённого ввода хранится в PostgreSQL.

## Переменные окружения

В Vercel → Project → Settings → Environment Variables добавьте:

- `BOT_TOKEN`: токен Telegram-бота. Если ранее публиковали/отправляли токен в чат, отзовите его через @BotFather и используйте новый.
- `DATABASE_URL`: строка подключения к PostgreSQL от вашего провайдера. Включите SSL, если этого требует провайдер.
- `TELEGRAM_WEBHOOK_SECRET`: случайная строка из латинских букв, цифр, дефиса и подчёркивания, длиной 32–64 символа.

Добавьте переменные для Production (и Preview, если нужно) и передеплойте проект после их создания.

## Развёртывание на Vercel

1. Импортируйте этот GitHub-репозиторий в Vercel.
2. Добавьте все три переменные окружения.
3. Подключите управляемую PostgreSQL-базу данных и скопируйте её connection string в `DATABASE_URL`.
4. Выполните Deploy.
5. Проверьте корневой адрес проекта: он должен вернуть JSON с `"ok": true`.
6. Зарегистрируйте webhook командой ниже.

Webhook регистрируется автоматически через Telegram Bot API, используя публичный адрес развернутого проекта:

```bash
BOT_TOKEN="..." TELEGRAM_WEBHOOK_SECRET="..." PUBLIC_BASE_URL="https://ВАШ-ПРОЕКТ.vercel.app" python scripts/set_webhook.py
```

Не добавляйте токен в GitHub или в исходный код. Запускайте команду в безопасной среде, где секреты не попадут в историю команд или логи.

## Важно

- Этот проект использует PostgreSQL; локальный SQLite-файл не подходит для serverless-функций Vercel.
- Telegram отправляет обновления на `/api/webhook`; запросы проверяются по заголовку `X-Telegram-Bot-Api-Secret-Token`.
- После смены домена Vercel повторно запустите `scripts/set_webhook.py`.
- Перед публичным использованием протестируйте добавление расходов, создание категории, отчёт и повторные webhook-запросы.
